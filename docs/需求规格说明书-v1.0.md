# 学习刷题 Agent 平台需求规格说明书

版本：v1.0（产品初稿）  
编写日期：2026-11-11  
用途：产品评审、原型设计、开发拆解和验收依据

## 1. 产品定位与范围

### 1.1 产品定位

面向自主学习者的 AI 学习与刷题平台，将多模型问答、分类题库、个性化学习计划、练习与测试、错题复习、学习视频搜索整合为一个学习闭环。

核心路径：选择学习目标 → 评估当前水平 → 制定计划 → 学习与刷题 → 定期测试 → 分析薄弱点 → 调整计划。

### 1.2 目标用户

| 用户 | 核心需求 |
| --- | --- |
| 自主学习者 | 按目标安排学习、理解知识、持续练习和复习 |
| 考试备考者 | 按考试范围刷题、模拟测试、追踪薄弱知识点 |
| 职业技能学习者 | 分类学习编程、语言及其他技能，查找配套视频 |
| 内容管理员 | 管理分类、题目、解析和学习资源，处理错误反馈 |
| 平台管理员 | 管理模型、访问权限、系统配置和运行情况 |

### 1.3 本版设计假设

1. 首期以个人学习为主，采用响应式 Web，兼顾电脑与手机浏览器。
2. 学习分类可配置；数学、语言、编程、职业考试等作为示例，不预先覆盖所有学科。
3. AI 辅助生成计划、讲解、出题、评分和复习建议，关键内容允许用户确认、编辑及纠错。
4. 首期支持平台配置模型，预留用户自带 API Key 的能力；两种模式的成本、权限和凭证分开管理。
5. 视频首期提供搜索结果、收藏和跳转观看；各平台接入范围以可用接口、授权和实际可获得的数据为准。
6. 当前目标是明确需求，具体技术栈、模型供应商、商业定价和首发学科在开发立项时确定。

### 1.4 目标与评估

- 用户能完成一次“设定目标—学习—做题—测试—复习”的完整流程。
- 首期重点观察：首次计划创建率、首次练习完成率、周学习活跃天数、计划完成率、错题复习完成率。
- 学习效果观察：相同知识点的后续答题正确率、测试表现变化；不得将不同难度试卷的原始分数直接视为能力提升。
- 性能与稳定性指标见第 10 节；业务指标的目标值在试运行获得基线后设定。

## 2. 版本规划

优先级定义：P0 为首版必须具备；P1 为完整学习体验所需的后续能力；P2 为扩展能力。

| 模块 | P0：首版 | P1：后续增强 | P2：扩展 |
| --- | --- | --- | --- |
| 账号与学习空间 | 账号、个人资料、目标、分类 | 多学习空间、通知偏好 | 班级、教师与组织 |
| 模型接入 | 至少两个独立模型配置、流式问答、用量记录 | 用户自带 Key、任务路由、多模型比较 | 更多协议和本地模型适配 |
| 学习问答 | 提问、提示、答案、解析、上下文 | 学习资料检索、图片提问、追问推荐 | 语音和多模态陪练 |
| 题库与练习 | 分类、知识点、筛选、练习、错题、收藏 | 文件批量导入、AI 出题、审核工作流 | 机构内容接入与共享题库 |
| 学习计划 | 目标、可用时间、计划生成、编辑与打卡 | 动态调整、补课安排、日历导出 | 多目标时间优化 |
| 测试 | 手动组卷、自动组卷、自定义周测/月测 | 高级组卷、试卷比较和更多题型 | 教师考试及协作 |
| 视频资源 | 一个可用来源端到端接入、跨平台架构、搜索与跳转 | 扩大来源、嵌入播放、学习记录 | 有授权的字幕检索和内容总结 |
| 数据分析 | 练习、测试、错题、计划的基础统计 | 知识点趋势和复习效果分析 | 更复杂的学习能力评估 |

首版不包含：视频下载与托管、付费课程转售、社交社区、直播授课、在线代码执行、自动购买资源、教师管理系统。编程题首期可作为主观题处理。

## 3. 核心业务流程

### 3.1 首次学习

注册或登录 → 选择学科及学习目标 → 填写当前水平、目标日期、每周可用时段 → 可选基础测评 → 生成计划草稿 → 用户确认 → 展示今日任务。

用户可以跳过测评；计划应标明当前依据为用户自述，并允许之后通过练习结果修正。

### 3.2 日常学习与刷题

打开今日任务 → 阅读学习内容或查找视频 → 按知识点练习 → 提交答案 → 查看判分及解析 → 错题进入复习队列 → 更新任务进度。

练习模式允许逐题看答案；测试模式默认交卷后统一展示答案。需要提示时，记录提示使用情况，以区分独立作答与辅助作答。

### 3.3 周测与月测

创建测试规则 → 到期生成待做试卷 → 用户开始测试 → 限时作答、自动保存 → 交卷 → 客观题判分、主观题辅助评分 → 生成报告 → 给出复习与计划调整建议。

到期生成试卷不等于自动开始计时；计时从用户点击开始时启动。

### 3.4 视频辅助学习

从知识点、题目解析或独立搜索入口进入 → 设置平台、语言、时长等可用筛选项 → 浏览带来源的结果 → 跳转原平台观看或收藏 → 返回平台标记学习完成。

## 4. 功能需求

### 4.1 账号、分类与学习目标

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| ACC-01 | P0 | 支持注册、登录、退出和账号恢复；同一用户的数据跨设备同步。具体登录方式由部署环境确定。 |
| ACC-02 | P0 | 用户可设置昵称、时区、每日学习时间、每周休息日和通知偏好。 |
| CAT-01 | P0 | 支持“内容类别—学科/课程—章节—知识点”的层级管理，题目可关联多个知识点。 |
| CAT-02 | P0 | 支持按分类、知识点、难度、题型、来源搜索与筛选；分类调整不应丢失历史学习记录。 |
| GOAL-01 | P0 | 用户可创建多个目标，指定范围、目标日期、当前水平和优先级；首页明确当前目标。 |
| GOAL-02 | P0 | 目标可暂停、完成或归档；归档后保留关联练习、计划和测试记录。 |

### 4.2 多模型 API 接入

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| MOD-01 | P0 | 通过适配层接入不同供应商；模型配置包括供应商、模型标识、端点、认证方式、超时、上下文及能力声明。 |
| MOD-02 | P0 | 管理员可新增、编辑、启停模型并测试连接；至少验证两个独立模型配置可完成完整问答。 |
| MOD-03 | P0 | 用户可从有权限的模型列表中选择模型；会话记录实际使用的模型与调用结果。 |
| MOD-04 | P0 | 支持流式输出、停止生成、重新生成；保留用户输入，失败后可重试。 |
| MOD-05 | P0 | 根据模型能力启用图片、结构化输出等选项；不支持的能力应禁用并说明。 |
| MOD-06 | P0 | 处理认证失败、余额不足、限流、超时和网络中断；错误信息不得泄露凭证。 |
| MOD-07 | P0 | 按用户、模型、任务记录请求数、可获得的 Token 用量及成本；价格和成本须标明来源与更新时间，缺失时显示未知或估算。 |
| MOD-08 | P0 | 支持用户级和平台级调用额度；达到硬限额后阻止新调用，不影响已有学习记录访问。 |
| MOD-09 | P1 | 用户可配置自己的 Key、测试连接和删除凭证；仅本人可使用，管理员界面不显示明文。 |
| MOD-10 | P1 | 可按问答、出题、评分等任务设置默认模型；跨供应商自动切换须由用户预先开启，并记录实际切换。 |
| MOD-11 | P1 | 支持同题多模型对比，分别展示回答、耗时和可获得的用量；不自动合并为权威结论。 |

补充规则：切换模型时说明将继续使用的会话上下文；平台应避免盲目重试造成重复消耗。供应商兼容某种 API 协议不代表支持全部能力，每个适配器需要独立验证。

### 4.3 学习 Agent 与问答解析

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| AGT-01 | P0 | 提供学习助手入口，可理解用户问题并调用平台已有的题库搜索、计划查询及视频搜索能力。 |
| AGT-02 | P0 | 支持“提示模式”“完整解析”“知识点讲解”“检查我的解法”四种交互；用户可指定讲解深度。 |
| AGT-03 | P0 | 对题目分别展示题干、用户答案、参考答案、判分、解析和关联知识点；展示来源及 AI 生成标识。 |
| AGT-04 | P0 | 解析应包含适用的方法、关键步骤、结论和常见错误；支持 Markdown、公式和代码块。 |
| AGT-05 | P0 | 支持会话历史、按目标关联会话、追问、重新生成和删除会话。 |
| AGT-06 | P0 | AI 可提出计划变更或新增学习任务，用户确认后写入；普通问答不得隐式修改计划和成绩。 |
| AGT-07 | P0 | 用户可反馈答案错误、解析不清或题意不完整，并查看处理状态。 |
| AGT-08 | P1 | 支持上传允许格式的学习资料，建立个人资料检索；回答引用可定位至资料及页码或段落。 |
| AGT-09 | P1 | 支持图片题识别；在识别存在歧义时让用户校正题干后再求解。 |

Agent 执行边界：只调用授权工具，限制单次任务步数和预算；资料、题目及网页文本作为数据处理，不能覆盖平台指令或获取 API Key。引用资料的回答应区分资料内容和 AI 推断；无法确认时明确表达不确定性。

### 4.4 题库管理

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| QB-01 | P0 | 支持单选、多选、判断、填空和简答题；统一保存题干、选项、答案、解析、知识点、难度、来源与分值。 |
| QB-02 | P0 | 题目支持公式、图片和代码；选项和答案采用稳定标识关联，随机排序后仍可正确判分。 |
| QB-03 | P0 | 支持手动录入、编辑、发布、下架和题目预览；用户可创建个人私有题目。 |
| QB-04 | P0 | 支持关键字搜索、组合筛选、收藏和按条件抽题；默认不向用户公开平台未发布题目。 |
| QB-05 | P0 | 区分平台共享题库与个人私有题库；所有题目记录来源类型、来源链接或说明及内容使用依据。 |
| QB-06 | P0 | 题目修改生成新版本；历史作答、成绩及已生成试卷关联原版本。 |
| QB-07 | P1 | 支持 CSV/JSON 模板批量导入，校验必填项、题型、选项和答案格式，逐行反馈错误及重复疑似项。 |
| QB-08 | P1 | 支持 AI 按知识点、题型、难度和数量出题；校验失败可修正，未经确认不得进入正式共享题库。 |
| QB-09 | P1 | 管理员可处理错误反馈，修订答案，必要时对受影响记录发起显式重评并保留前后结果。 |

内容状态建议：草稿 → 待审核 → 已发布 → 已下架。AI 生成题与已核验题分开标识，避免把未经审核的答案当作已验证标准答案。

### 4.5 刷题、错题与复习

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| PRA-01 | P0 | 提供顺序练习、随机练习、知识点专项、错题重做和收藏练习。 |
| PRA-02 | P0 | 作答记录答案、耗时、提交时间、题目版本、提示及看答案情况；重复点击提交只生成一次结果。 |
| PRA-03 | P0 | 客观题按明确规则判分；多选首期采用全对得分，漏选或错选不得分，并在作答前说明。 |
| PRA-04 | P0 | 填空题支持多个可接受答案及显式的空格、大小写规则；复杂表达式不做无依据的等价判断。 |
| PRA-05 | P0 | 简答题采用评分标准和 AI 辅助评分，展示评分依据，允许用户复核并记录修正原因。 |
| PRA-06 | P0 | 答错题自动加入错题本；支持手动加入、原因标签、笔记、重做和移出，保留历史。 |
| PRA-07 | P0 | 错题按可配置间隔安排复习；首期可使用 1、3、7、14 天作为默认规则，由用户调整。 |
| PRA-08 | P1 | 根据近期答题、提示使用和复习结果推荐题目，解释推荐原因；用户可切回手动选择。 |

掌握度为学习参考指标，应展示依据和样本量。查看答案后的答对结果不能直接计入独立答题正确率。

### 4.6 学习计划、学习安排与内容

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| PLN-01 | P0 | 根据目标、知识点范围、当前水平、截止日期和可用时段生成计划草稿。 |
| PLN-02 | P0 | 计划分为阶段、周、日三级；每日任务可为知识学习、视频学习、练习、复习或测试。 |
| PLN-03 | P0 | 每项任务包含标题、知识点、预计时长、完成条件和关联资源；学习内容可由管理员维护或用户自建。 |
| PLN-04 | P0 | 支持新增、编辑、移动、跳过任务，调整预计时长与休息日；保留调整记录。 |
| PLN-05 | P0 | 当计划超出可用时间时展示差额，提供延期、缩小范围或增加时间的选择，不静默塞入额外任务。 |
| PLN-06 | P0 | 首页展示今日任务、逾期任务及本周进度；刷题和测试可自动关联完成情况，阅读和视频可手动完成。 |
| PLN-07 | P0 | 任务逾期不自动删除；用户可选择顺延、重新分配或跳过。 |
| PLN-08 | P1 | 根据测试和执行情况提出计划调整建议，展示变更前后差异，确认后生效。 |
| PLN-09 | P1 | 支持站内提醒，预留邮件、推送及日历导出；外部通知需用户开启并配置渠道。 |

首期完成条件示例：知识学习为手动确认；练习为完成指定题数；复习为完成指定错题；测试为提交试卷。任务完成与知识掌握分别统计。

### 4.7 自定义测试、周测与月测

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| EXM-01 | P0 | 用户可创建一次性或重复测试，配置范围、题型、数量、难度比例、分值、时长和答题说明。 |
| EXM-02 | P0 | 支持每周指定星期与时间、每月指定日期与时间；按用户时区执行，可暂停和恢复。 |
| EXM-03 | P0 | 支持手动选题及按规则自动组卷；可设置近期做过题目的排除时间窗。 |
| EXM-04 | P0 | 组卷前校验题量、题型及分值；题库不足时列出缺口，由用户调整条件，不能静默重复或改变规则。 |
| EXM-05 | P0 | 开始前保存试卷题目、答案、评分规则及版本快照；测试中题库更新不得影响本次评分。 |
| EXM-06 | P0 | 支持倒计时、答题卡、标记待检查、自动保存及断线恢复；测试中不提供标准答案入口。 |
| EXM-07 | P0 | 到时自动交卷；交卷接口幂等，重复请求不重复创建成绩。 |
| EXM-08 | P0 | 报告展示总分、各题得分、用时、知识点表现、错题与后续学习建议；主观题标明 AI 辅助评分。 |
| EXM-09 | P0 | 允许复核与重评；保留原成绩、调整理由、操作者及时间。 |
| EXM-10 | P1 | 支持全范围测试、近期所学测试、薄弱知识点测试等模板及试卷报告对比。 |

调度规则：

- 月测选择 29、30 或 31 日，而当月无该日期时，默认在当月最后一天生成，并在设置中明确展示。
- 到期仅创建一份待做试卷；后台任务重复执行、服务重启均不得重复生成。
- 错过的测试保留待做状态，可由用户跳过；恢复已暂停规则后，不批量补生成暂停期间的测试。
- 已开始测试按服务端截止时间计时，离开页面不暂停；客户端倒计时仅用于显示。
- 断网时保留本地未同步答案并展示状态；已到截止时间后不得静默覆盖已交卷答案，可提供记录恢复情况的复核入口。
- 用户修改时区影响后续周期，不改变已开始测试的截止时间。

### 4.8 多平台学习视频搜索

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| VID-01 | P0 | 提供统一搜索入口，支持关键词、知识点和题目衍生搜索；通过来源适配器查询可接入的平台。 |
| VID-02 | P0 | 结果展示标题、平台、作者、原始链接，以及接口可提供的封面、时长、发布时间和简介；缺失字段不编造。 |
| VID-03 | P0 | 按平台筛选；语言、时长、发布时间等条件在数据源支持时提供，说明当前筛选范围。 |
| VID-04 | P0 | 支持从学习任务或解析页一键搜索相关视频、收藏资源并加入学习任务。 |
| VID-05 | P0 | 部分来源失败时保留其他结果，显示失败来源与重试入口；没有结果时给出关键词调整建议。 |
| VID-06 | P0 | 相同来源链接去重；排序可基于文本匹配和来源元数据，标明推荐依据。 |
| VID-07 | P1 | 扩展更多平台，按可用接口支持内嵌播放；无法内嵌时继续提供原站跳转。 |
| VID-08 | P1 | 对具备获取权限的字幕提供摘要和知识点关联，并标记摘要为 AI 生成。 |

候选来源包括哔哩哔哩、YouTube 及其他教育平台，属于待评估接入清单。本需求不承诺任意平台均有可用搜索 API。正式上线前须明确首期来源、访问区域、使用方式和可用字段。付费或登录限制在原平台处理。

## 7. 系统模块与接口边界

建议划分为前端应用、业务服务、模型适配层、资源搜索适配层、定时任务与异步任务模块、数据存储。初期可作为同一应用部署，模块边界不等于必须采用微服务。

主要业务接口能力：

1. 身份认证、用户设置和权限校验。
2. 模型列表、配置测试、问答流、停止生成、调用记录。
3. 分类、题目搜索、题目版本、作答与错题。
4. 目标、计划生成任务、计划确认和每日任务。
5. 测试规则、组卷任务、开始测试、保存答案、交卷和报告。
6. 视频聚合搜索、资源收藏及任务关联。
7. 管理后台、内容反馈、审计和监控。

接口通用要求：分页、统一错误码、服务端鉴权、请求追踪；涉及提交、组卷、计费记录的操作具备幂等机制；AI 出题、计划生成等长任务支持查询状态和失败重试。对外端点配置仅限授权角色，并验证地址，防止访问内部服务和云元数据地址。

## 8. 权限、隐私与内容规则

- 用户只能访问自己的会话、计划、私有题库、测试记录与模型凭证；共享内容按发布权限访问。
- API Key 在服务端加密存储，仅后端调用时解密使用；前端、日志、导出和错误信息不返回明文。
- 页面说明哪些资料、题目或会话会发送给选定模型；不同供应商的数据处理设置在接入时明确。
- 用户可删除会话、资料及个人学习内容；账号删除与备份清理遵循平台公开的数据保留策略。
- 导出仅包含用户有权导出的数据，排除受限共享题目和第三方受限内容。
- 引用题目、视频及资料保留来源；平台维护内容使用依据，提供错误及侵权反馈处理入口。
- 对上传文件限制类型与大小，验证实际内容；只在用户授权范围内建立检索索引。
- 首期不自动公开用户对话、题目、笔记、测试成绩及上传资料。
- 删除、重评、调额等操作应有清晰反馈；影响历史记录的操作保留必要审计信息。

## 9. 异常与一致性要求

| 情况 | 系统行为 |
| --- | --- |
| 模型限流或超时 | 保留问题及已接收内容，展示失败原因，允许重试；按配置控制重试次数 |
| AI 返回不符合格式 | 先校验，再有限修复；仍失败则不写入正式题目、计划或成绩 |
| AI 评分不可用 | 保留答卷，主观题标记待评分；客观题结果可先显示，总成绩标记未完成 |
| 题目参考答案被修正 | 历史成绩保持原版本，显式重评后生成新的成绩版本 |
| 调度重复触发 | 以测试规则和计划执行时间作为唯一业务键，只生成一次 |
| 用户多设备作答 | 检测并发版本冲突，避免后保存的旧答案覆盖新答案；测试开始时提示会话状态 |
| 视频平台不可用 | 单来源失败隔离，显示可用结果和失败说明 |
| 余额不足 | 中止新的 AI 请求，允许继续非 AI 练习、查看记录和使用已生成计划 |
| 浏览器刷新或退出 | 恢复已同步答案；已开始测试继续计时 |

## 10. 非功能需求

下列数值为首版建议验收目标，须在确定部署资源后锁定测试环境与负载模型。

| 类别 | 建议要求 |
| --- | --- |
| 页面性能 | 指定测试环境中，核心页面主要内容可见时间 P95 ≤ 3 秒；第三方 AI 与视频数据单独展示加载状态 |
| 业务接口 | 在 100 个并发活跃用户、约定读写负载下，普通查询及提交接口响应 P95 ≤ 1 秒；不含外部调用和长任务 |
| AI 交互 | 前端提交后 1 秒内显示请求状态；首字延迟受模型供应商影响，独立监测并展示超时状态 |
| 数据保存 | 测试答案在变更后 5 秒内尝试同步；立即显示保存中、已保存或失败，失败后允许重试 |
| 可用性 | 试运行后建议以月度 99.5% 为自有服务目标；第三方故障单独记录并提供降级体验 |
| 兼容性 | 支持主流桌面与移动浏览器，首发浏览器清单及最低版本在测试计划中确定 |
| 可访问性 | 关键操作可键盘完成，表单有标签，错误不只依赖颜色提示 |
| 安全性 | 全程加密传输、服务端权限校验、调用限额、上传校验、敏感字段脱敏 |
| 备份恢复 | 建议每日备份；首版建议 RPO ≤ 24 小时、RTO ≤ 8 小时，并执行恢复演练 |
| 可观测性 | 监控接口错误率、模型失败率、调用用量、任务积压、搜索源故障和调度执行情况 |
| 可维护性 | 模型、视频源及题型通过清晰接口扩展；核心规则可配置，配置变更可审计 |

## 11. 首版验收用例

| 编号 | 场景与通过条件 |
| --- | --- |
| AC-01 | 新用户选择一门学科，设定目标、期限和每周时段，能生成、修改并确认包含学习、练习及复习任务的计划。 |
| AC-02 | 两个独立模型配置分别完成相同问题的问答；会话正确标记模型，认证失败与超时均有可理解的错误反馈。 |
| AC-03 | 用户对一道题请求提示，再请求完整解析；系统正确区分两类结果，且记录提示使用状态。 |
| AC-04 | 用户按知识点与难度筛选题目，完成包含五种首期题型的练习，得到对应判分或待复核状态。 |
| AC-05 | 答错题进入错题本，可添加原因与笔记，重做后保留前后记录及下一次复习安排。 |
| AC-06 | 用户创建每周一次和每月一次测试；按指定时区生成，重复执行后台任务不生成重复试卷。 |
| AC-07 | 选择每月 31 日并模拟无 31 日的月份，试卷按界面说明在月底生成。 |
| AC-08 | 组卷所需题量不足时明确指出缺口，不生成违背规则的试卷；修改条件后可成功生成。 |
| AC-09 | 测试刷新页面后已同步答案恢复，倒计时与服务端一致；截止后自动交卷，重复交卷只有一份有效结果。 |
| AC-10 | 测试开始后编辑源题目，不改变本次题干及评分；显式重评保留原成绩与修正记录。 |
| AC-11 | 通过一个实际可用的视频来源搜索知识点，结果包含有效原站链接，可收藏并关联学习任务；单来源失败不阻塞其他来源。 |
| AC-12 | 用户 A 无法通过界面或直接调用接口读取用户 B 的私有题库、会话、计划、试卷和模型配置。 |
| AC-13 | 在网络请求、页面、普通日志及导出中检查不到完整 API Key；额度耗尽后仍可查看既有学习内容。 |
| AC-14 | AI 计划或题目返回非法结构、提示注入或超预算请求时，不产生越权操作及未验证的正式记录。 |
| AC-15 | 日、周统计与原始作答、任务及测试记录一致，使用提示或查看答案的记录能与独立作答区分。 |

## 13. 立项时需确认的产品决策

以下事项不阻止原型设计，但应在对应开发开始前明确：

1. 首发服务的人群与一至两个具体学科，是否针对某类考试。
2. 首发题库从何处获得、规模与使用依据，谁负责内容审核。
3. 首发模型供应商、平台统一付费还是用户自带 Key，以及单用户预算。
4. 首发视频来源、部署地区、可用接口及是否需要登录。
5. 登录方式、部署环境、预计用户量，是否需要商业收费。
6. 是否明确面向未成年人；如是，需要另行明确适用的账号、监护及数据要求。
7. 主观题评分是否仅作个人学习参考，是否需要教师或管理员参与复核。
8. 首版是否要求邮件或移动推送；如要求，需增加渠道配置和送达验收。

建议先上线一个完整学科的学习闭环，再通过同一套分类、题库和适配机制扩展内容与平台。
