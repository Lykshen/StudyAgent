## 1. 范围与原则

StudyAgent 是本地运行的学习与刷题平台。框架通用，适用于任何学科；第一个内置学科是「编程机考」。

| 原则 | 含义 |
| --- | --- |
| 数据在本地 | 所有数据存在运行平台的电脑上的一个 SQLite 文件里；手机和其它电脑通过局域网访问同一份数据 |
| 先学后练 | 每个模块先安排课程，再安排题目；题目按 L1 → L4 由易到难 |
| AI 只提议，不擅改 | AI 产出的计划变更、题目、分类、课程、导入结果，都要用户确认后才写入；普通问答不修改任何学习数据 |
| 规则明确 | 判分、组卷、复习都有固定规则并在界面上说明；条件不满足时报告缺口，不静默降级 |
| 多人可扩展 | 所有个人数据按 `user_id` 隔离；平台题库共享；接口全部带鉴权 |
| 多平台同源 | 桌面窗口、浏览器、手机 App 加载同一套前端，调用同一套 HTTP 接口 |

## 2. 架构

```
 ┌──────────── 客户端（同一套前端 studyagent/web） ────────────┐
 │  桌面窗口 (pywebview)   浏览器   手机 App (Capacitor) / PWA   │
 └───────────────┬──────────────────────────────────────────────┘
                 │ HTTP + JSON，流式回复用 SSE；Bearer 访问码鉴权
 ┌───────────────▼──────────────────────────────────────────────┐
 │ Flask 应用 studyagent/api.py                                  │
 │  ├─ learning.py  题目、进度、间隔复习、计划引擎                │
 │  ├─ exams.py     组卷、计时、交卷、复核                        │
 │  ├─ grading.py   各题型判分；编程题子进程运行                   │
 │  ├─ importer.py  文件转文字、拆题、校验                        │
 │  ├─ agents.py    智能体、工具、提议、结构化 AI 任务             │
 │  └─ llm.py       模型适配层（OpenAI 兼容 / Anthropic）、用量    │
 └───────┬───────────────────────────┬──────────────────────────┘
         │                           │ HTTPS
   SQLite (WAL)                 模型服务商 API、YouTube Data API
   data/studyagent.db
```

### 运行形态

| 形态 | 入口 | 监听地址 | 数据目录 |
| --- | --- | --- | --- |
| 源码 | `run.py` | 默认 `127.0.0.1:8765`；`--lan` 或设置里开启后为 `0.0.0.0` | `data/`，或 `--data` |
| 桌面程序 | `desktop.py`（打包为 exe / app） | 从 8765 起找一个空闲端口；开启局域网时为 `0.0.0.0` | Windows `%APPDATA%\StudyAgent`；macOS `~/Library/Application Support/StudyAgent`；Linux `~/.local/share/StudyAgent` |
| 手机 App | `mobile/`（Capacitor 壳） | 不运行服务端，连接电脑上的服务 | 无（数据在电脑上） |

- 数据目录由环境变量 `STUDYAGENT_DATA` 决定。
- 局域网开关保存在数据目录的 `config.json`，修改后需要重启生效。

### 桌面程序

- `desktop.py` 在后台线程启动服务（werkzeug `make_server`），再用 pywebview 打开原生窗口。
- 系统缺少 WebView 组件时，改用默认浏览器打开。
- 打包后的程序里没有单独的 `python.exe`。编程题判题时，程序以 `StudyAgent.exe --sa-harness <harness> <src> <cases>` 的方式重新启动自己来运行学生代码（见 `grading.python_cmd` / `run_harness_inline`）。
- 学生代码常用的标准库要在 `packaging/StudyAgent.spec` 的 `student_libs` 里显式打包。

### 手机 App

- `mobile/` 是 Capacitor 工程。App 内置一个连接页 `mobile/www/index.html`：
  - 输入电脑地址后，用 `GET /api/docs` 测试能否连通；
  - 连通后把 WebView 导航到电脑上的服务；
  - 最近连接过的地址存在本机，下次自动连接。
- App 的 User-Agent 附加 `StudyAgentApp`。前端据此在「设置」里显示「连接其它电脑」，回到连接页。
- 安卓需要允许明文 HTTP（`usesCleartextTraffic`），因为局域网服务没有 HTTPS。CI 打包时自动写入。
- 前端同时是 PWA（`manifest.json`、`sw.js`）。Service Worker 只缓存界面外壳，`/api/` 请求总是走网络。

## 4. 数据模型

SQLite，WAL 模式。表结构在 `db.py` 的 `SCHEMA` 中。

- 启动时 `db.init()` 建表，并执行增量迁移（只加列，不删列）。
- JSON 字段以文本存储，用 `db.J()` 读、`db.dumps()` 写。

| 表 | 作用 | 归属 |
| --- | --- | --- |
| `users` | 用户；`token` 即访问码；`role` 为 `admin` / `user` | — |
| `subjects` | 学科；`exam_profile` 为考试结构（[8.3](#83-考试结构)） | `owner_id` 为空表示平台学科 |
| `categories` | 模块；`lesson_only` 表示只有课程没有题 | 学科 |
| `questions` | 题目（[8.1](#81-题目)）；`tier` 层级 1–4；`cls_by` / `cls_reason` 记录分类来源和理由；`version` 版本号 | `owner_id` 为空表示平台题 |
| `question_versions` | 题目每次修改前的快照 | 题目 |
| `lessons` | 模块课程（[8.2](#82-课程)）；`generated_by` 记录 builtin / AI | 模块 |
| `user_lessons` | 用户课程进度、测验状态 | 用户 |
| `progress` | 用户 × 题目：状态、笔记、错因标签、用时、使用过的帮助（`assist`）、保存的代码、收藏 | 用户 |
| `attempts` | 每次作答：答案、得分、题目版本、是否独立完成；`idem` 唯一，防止重复提交 | 用户 |
| `reviews` | 错题复习：轮次、到期日、历史 | 用户 |
| `goals` | 学习目标和计划参数 | 用户 |
| `skipped` | 跳过的题 | 用户 |
| `exams` | 试卷：快照、答案、标记、开始和截止时间、结果、复核记录 | 用户 |
| `exam_skips` | 跳过的定期测试 | 用户 |
| `study_log` | 每日有效学习时长 | 用户 |
| `conversations` / `messages` | 智能体对话；`messages.status` 为 `streaming` / `done` / `error` | 用户 |
| `proposals` | AI 提出、等待确认的变更 | 用户 |
| `model_configs` | 模型配置（含 API Key） | 用户 |
| `task_routes` | 任务 → 模型 | 用户 |
| `usage` | 每次模型调用的用量、耗时、错误 | 用户 |
| `resources` | 收藏的视频 | 用户 |
| `audit` | 关键操作审计 | — |
| `feedback` | 题目问题反馈 | 用户 |
| `meta` | 平台级键值（如默认考试结构） | — |

### 隔离规则

- 用户只能读写 `user_id` 等于自己的行。
- 题目对用户可见的条件：
  - 平台题（`owner_id IS NULL`）并且 `status='published'`；或
  - 自己的题（`owner_id = 自己`）。

  实现在 `learning.visible_questions`。
- 返回给前端的题目经过 `learning.public_question`。答案、隐藏用例、参考解只在作答后或用户主动查看时返回，并记入 `progress.assist`。

## 5. 业务规则

### 5.1 层级

| 层级 | 名称 | 判断标准 |
| --- | --- | --- |
| 1 | 入门 | 单一知识点，按题意直接实现 |
| 2 | 基础 | 套用一个标准方法或模板 |
| 3 | 进阶 | 组合两种方法，或边界、规则较复杂 |
| 4 | 挑战 | 综合性强，需要较深的分析或设计 |

同一模块内，题目按层级升序排列，层级相同再按分值排列，外部题排在后面。

### 5.2 判分（`grading.py`）

| 题型 | `type` | 规则 |
| --- | --- | --- |
| 单选 | `single` | 选项下标相等得满分 |
| 多选 | `multi` | 选项下标集合完全相等得满分，否则 0 分 |
| 判断 | `judge` | 布尔值相等得满分 |
| 填空 | `fill` | 按空计分。每空可有多个可接受答案；`fill_rules` 控制是否区分大小写、是否忽略空格（默认不区分大小写、忽略空格）。不做表达式等价判断 |
| 简答 | `short` | 模型按 `rubric` 打分，返回得分、命中和缺失的要点、依据；结果标明「AI 评分」 |
| 编程 | `code` | 本机子进程运行，得分 = 通过用例数 / 总用例数 × 分值 |
| 外部 | `external` | 不判分，由用户标记完成 |

#### 编程题运行

- **函数入口：** `def solve(...)`；或 `class Solution` 的第一个公有方法。
- **参数格式：** 每个用例为 `{"args": [...], "expect": 值}`。
- **比较方式：** 返回值序列化为 JSON 后比较。
- **预置导入：** Python 预置与力扣一致的常用导入：
  - `typing`、`collections`、`heapq`、`bisect`、`itertools`、`functools` 的全部名字；
  - `math` 的常用函数，以及 `re`、`string`、`operator`、`random` 模块。
- **超时：** 每个用例单独计时，默认 5 秒。某个用例超时后终止进程，后面的用例记为 `SKIP`。
- **结果代码：**

  | 代码 | 含义 |
  | --- | --- |
  | `AC` | 通过 |
  | `WA` | 答案错误 |
  | `RE` | 运行错误 |
  | `TLE` | 超时 |
  | `SKIP` | 未运行（前一用例超时） |
- **支持的语言：** Python，以及装有 Node.js 时的 JavaScript。其它语言只能用 AI 检查。
- **用例范围：** 「运行」只用题面样例（`examples` 中带 `args` / `expect` 且未标 `doubt` 的）；「提交」再加上全部 `hidden`。

#### 独立完成

作答前用过提示、看过解析或参考答案（`progress.assist` 中有记录）时，`attempts.independent = 0`。统计「独立通过率」时只计 `independent = 1` 的作答。

#### 幂等

提交接口接受客户端生成的 `idem`。同一 `idem` 重复提交时，返回第一次的结果，不新增记录。

### 5.3 错题复习

1. **进入错题本：** 作答得分低于满分，或用户把题标为「需复习」。
2. **复习间隔：** 取自目标的 `intervals`，默认 `[1, 3, 7, 14]`。
3. **复习结果：** 到期当天重做：
   - 满分：进入下一轮；
   - 否则：回到第一轮。

   未到期时重做不算复习。
4. **掌握：** 完成全部轮次后，`done = 1`。
5. **历史保留：** 每次复习记入 `history`。

### 5.4 计划引擎（`learning.build_plan`）

**输入**
- 目标：开始日期、考试日期、每日小时数、周测星期、月测日期、是否包含 L4、复习间隔、语言；
- 题库、课程、用户进度、跳过的题。

**计算步骤**

1. **天数与冲刺期**
   - 总天数：开始日期到考试日期之间的天数。
   - 冲刺期：总天数 ≥ 14 时，最后 `max(3, 总天数 × 15%)` 天为冲刺期，不安排新内容。
2. **测试日**

   | 测试 | 安排在 |
   | --- | --- |
   | 周测 | 每周指定的星期 |
   | 月测 | 每月指定的日期；该月没有这一天时，取月末 |
   | 最后一天 | 固定是月测（全真模拟） |

   测试日可用于学习的时间扣除 150 分钟。
3. **候选题**
   - 未跳过；
   - 不是在目标开始前就已完成的题；
   - 未勾选「包含挑战题」时，排除 L4（已校验的核心题除外）。
4. **容量检查**
   - 需要时间 = 未学课程时长 + 候选题耗时之和；
   - 可用时间 = 学习期每天预算之和。
   - 超出时按 `overflow` 处理：

     | 取值 | 处理 |
     | --- | --- |
     | `trim` | 从优先级最低、最费时的题开始去掉，已校验的题保留 |
     | `extend` | 推迟考试日期 |
     | `hours` | 增加每天时间；同时给出建议的每日小时数 |
5. **排序**
   - 按模块顺序：先排模块课程，再排该模块的题（层级升序）；
   - 不属于任何模块的题排在最后。
6. **分配**
   - 依次放入学习期每天：剩余预算 ≥ 任务耗时 × 70%，或当天还没有任务时，放入当天；
   - 剩下的任务轮流分配到冲刺期；
   - 冲刺期没有任务的天安排复习。
7. **输出**
   - 每天：任务、负荷、超出的分钟数；
   - 整体：缺口、处理方式、被去掉的题。

**逾期**
- 计划日期早于今天、仍未完成的题列为逾期，不删除。
- 用户可以：
  - 整体从今天起重新排期（开始日期改为今天）；
  - 逐题跳过。

### 5.5 测试（`exams.py`）

**组卷（`generate`）**

1. **范围：**

   | 取值 | 含义 |
   | --- | --- |
   | `learned` | 计划中已到达的模块 |
   | `all` | 全部 |
   | `weak` | 薄弱 |
   | `custom` | 手动选题 |
2. **按考试结构抽题：** 逐部分按题型、层级、题量抽题，排除最近 `recent_window` 天（默认 14）做过的题。
3. **题量不足：** 返回缺口（哪一部分、要几道、有几道），不生成试卷。用户可以放宽条件，例如允许近期做过的题。
4. **AI 出题：** 选「AI 出题」时，由模型按结构生成整套新题，试卷标明 AI 生成。

**创建（`create`）**
- 保存试卷快照：题干、选项、答案、用例、分值、题目版本。
- 之后修改题库，不影响这份试卷的显示和评分。

**开始（`start`）**
- 记录 `start_at`，并以服务器时间计算 `deadline_at`。
- 客户端倒计时以服务器返回为准。

**作答中**
- 答案和「待检查」标记自动保存（`save_answers`）。
- 不返回答案。
- 智能体和题目 AI 接口对该用户返回 409。

**交卷（`finish`）**
- 用状态转换 `running → done` 保证幂等：重复请求返回已有结果。
- 读取试卷时如果已过截止时间，自动交卷。

**报告**
- 总分、每题得分与用时、各模块表现、错题；
- 错题自动进入错题本。

**复核（`adjust`）**
- 修改单题得分需要填写理由；
- 原分数、新分数、理由、操作者、时间写入 `adjustments`，同时写审计日志。

**定期测试**
- 由计划中的测试日生成。
- 同一目标、同一日期最多一份试卷（唯一索引 `exam_sched`），重复触发不会重复生成。

### 5.6 导入与分类（`importer.py`、`agents.classify`）

**导入**

1. **提取文字：** 支持 `.txt` `.md` `.json` `.csv` `.pdf`（pdfplumber 或 pypdf）`.docx`。
2. **分段：** 按长度分段，每段调用一次「导入题目」任务的模型，要求输出 JSON。
3. **校验：** `normalize` 逐题校验并修正格式：
   - 选项字母转下标；
   - 判断题文字转布尔；
   - 填空答案统一为二维数组；
   - 编程题样例解析出 `args` / `expect`。

   缺字段的题记入 `problems`。
4. **检查：** 结果在后台任务中生成，前端轮询（`/api/jobs/<id>`）。用户检查、修改、勾选后，调用 `/api/import/save` 才写入。
   - 有问题的题和同名题默认不勾选。
   - 新出现的模块名在保存时创建。

**分类分层**
- 每批 10 题，模型返回每题的模块、层级、知识点和理由。
- 用户勾选采用后，写入 `category_id` / `tier` / `points`，并记录 `cls_by='ai'` 和 `cls_reason`。

## 6. 模型接入与智能体

### 6.1 适配层（`llm.py`）

**接口**

| 接口 | 服务商 | 请求格式 |
| --- | --- | --- |
| `openai` | DeepSeek、通义千问、Kimi、GLM、OpenAI、本地模型、其它兼容服务 | `POST {base_url}/chat/completions` |
| `anthropic` | Claude | `POST {base_url}/v1/messages` |

**能力**
- 两种接口都支持：
  - 流式输出（SSE）；
  - 工具调用；
  - 推理内容（`reasoning_content` / `thinking`）；
  - JSON 输出（`json_mode`）。
- 标准库 `urllib` 实现，不依赖服务商 SDK。

**调用约定**
- 统一入口：`llm.chat(cfg, messages, tools=None, on_text=None, json_mode=False, max_tokens=None, user_id=None, task="chat", on_reason=None)`。
- 每次调用，无论成功失败，都写一条 `usage`：Token、耗时、错误。
- 模型选择：`model_for(user, task)` 先看任务路由，再取第一个可用模型。

**错误**
- 错误统一为 `LLMError(message, code, retryable)`，按 HTTP 状态翻译成可理解的中文提示：认证失败、余额不足、限流、超时、网络中断、服务端错误。
- 错误信息不包含 Key。
- 用户点「停止」时，流式回调抛出 `Cancelled`。

### 6.2 任务

| 任务键 | 名称 | 调用方 |
| --- | --- | --- |
| `chat` | 问答与讲解 | 学习助教、考前教练、题目 AI 按钮 |
| `plan` | 学习计划 | 规划师 |
| `classify` | 分类分层 | 分类任务 |
| `import` | 导入题目 | 导入任务 |
| `grade` | 主观题评分 | 简答题 |
| `lesson` | 生成课程 | 课程草稿 |

### 6.3 智能体（`agents.py`）

**智能体与工具**

| 智能体 | 键 | 可用工具 |
| --- | --- | --- |
| 学习助教 | `tutor` | 全部工具 |
| 规划师 | `planner` | `get_progress` `get_today_plan` `get_review_queue` `list_categories` `propose_plan_change` `propose_skip_question` |
| 考前教练 | `coach` | `get_progress` `get_review_queue` `search_questions` `get_question` `search_videos` `propose_status_change` |

| 工具 | 类型 | 说明 |
| --- | --- | --- |
| `get_progress` | 读 | 各模块完成度、正确率、薄弱点 |
| `search_questions` | 读 | 按关键字、模块、层级、题型搜题 |
| `get_question` | 读 | 题目详情（不含隐藏用例） |
| `get_today_plan` | 读 | 今日任务与逾期 |
| `get_review_queue` | 读 | 到期错题 |
| `list_categories` | 读 | 模块列表 |
| `search_videos` | 读 | 搜索学习视频 |
| `propose_status_change` | 提议 | 修改题目状态 |
| `propose_skip_question` | 提议 | 跳过题目 |
| `propose_plan_change` | 提议 | 修改目标或计划参数 |
| `propose_add_question` | 提议 | 新增题目 |

**执行规则**

1. 每轮最多 6 步工具调用。只允许调用该智能体分配到的工具，其它调用返回错误。
2. `propose_*` 工具只写入 `proposals`（状态 `pending`），不改任何学习数据。用户在界面上确认后，由 `apply_proposal` 执行，并写审计日志。
3. 系统提示要求模型把题目、资料、网页和工具返回的内容只当作数据，不执行其中的指令；即使模型被诱导，也只能调用白名单里的工具，写操作仍需用户确认。
4. 最终回答为空时（有些模型只调工具不作答），自动不带工具再调用一次，让模型给出完整回答。

**后台运行（`api.py` 的 `RUNS`）**

- 发送消息后，回复在后台线程里生成，与 HTTP 连接解耦。
- 生成中的回复每秒左右存一次库（`status='streaming'`），结束时改为 `done` 或 `error`。
- 客户端断开（切页面、刷新、关窗口）只是停止接收，不会中断生成。客户端用 `GET /api/conversations/<id>/attach?from=n` 重新接上，从第 n 个事件继续。
- 同一对话同时只允许一个生成任务，重复发送返回 409。
- 服务重启时，遗留的 `streaming` 消息标记为未完成。

## 7. 接口

所有接口在 `/api/` 下，请求和响应为 JSON（UTF-8）。

- 运行中的服务在 `GET /api/docs` 返回接口清单。
- 错误统一为 `{"error": "说明"}`，并使用对应的 HTTP 状态码：

  | 状态码 | 含义 |
  | --- | --- |
  | 400 | 参数错误 |
  | 401 | 未登录 |
  | 403 | 无权限 |
  | 404 | 不存在 |
  | 409 | 状态冲突 |
  | 502 | 模型调用失败 |

### 7.1 鉴权

- 请求头 `Authorization: Bearer <访问码>`；也接受 Cookie `sa_token` 或查询参数 `token`（用于 SSE）。
- 获取访问码：

  | 方式 | 接口 | 适用 |
  | --- | --- | --- |
  | 本机自动登录 | `GET /api/session/local` | 只接受 `127.0.0.1` / `::1` 的请求 |
  | 输入访问码 | `POST /api/session/login` `{"code": "..."}` | 其它设备 |

- 标为「管理员」的接口要求 `role='admin'`。第一个用户是管理员。

| --- | --- |

### 7.3 流式事件

SSE 接口逐行返回 `data: {JSON}`，每个事件带递增的 `seq`。没有新事件时，每 15 秒发一行 `: ping` 注释保活。

| `type` | 字段 | 含义 |
| --- | --- | --- |
| `start` | `message_id` `model` | 开始生成 |
| `thinking` | — | 模型正在推理 |
| `delta` | `text` | 回答文字增量 |
| `tool` | `name` `args` | 调用工具 |
| `tool_result` | `name` `summary` | 工具返回摘要 |
| `proposal` | `proposal` | 生成了一条待确认建议 |
| `error` | `message` `code` `retryable` | 失败 |
| `stopped` | — | 用户停止 |
| `done` | `content` `model` | 结束 |

## 8. 数据格式

### 8.1 题目

`POST /api/questions` 和导入保存时使用的结构：

```json
{
  "id": "可选，不填自动生成",
  "subject_id": 1,
  "category_id": 3,
  "type": "single | multi | judge | fill | short | code | external",
  "title": "题名",
  "stem": "题面，Markdown",
  "options": ["选项A", "选项B"],
  "answer": "见下表",
  "analysis": "解析，Markdown",
  "tier": 2,
  "score": 5,
  "points": ["知识点"],
  "source": "来源说明",
  "source_ref": "来源链接",
  "extra": {}
}
```

| 题型 | `answer` | `extra` |
| --- | --- | --- |
| `single` | 选项下标，如 `1` | — |
| `multi` | 下标数组，如 `[0, 2]` | — |
| `judge` | `true` / `false` | — |
| `fill` | 每空的可接受答案，如 `[["北京", "Beijing"], ["1949"]]` | `fill_rules: {case_sensitive, ignore_spaces}` |
| `short` | 评分要点文字 | `rubric` |
| `code` | — | `examples: [{input, output, args, expect, note}]`、`hidden: [{args, expect}]`、`params`（参数名）、`ref`（参考解） |
| `external` | — | `url`（原题链接）、`no`、`level` |

### 8.2 课程

`lessons.content`：

```json
{
  "key": "T3",
  "name": "模块名",
  "intro": "这个模块学什么",
  "minutes": 40,
  "concepts": [{"t": "概念标题", "b": "说明，Markdown", "code": "可选示例代码"}],
  "signals": ["看到……就想到……"],
  "templates": [{"t": "模板名", "code": "代码"}],
  "example": {"id": "题目 id", "steps": ["解题步骤"]},
  "pitfalls": ["常见错误"],
  "quiz": [{"q": "题目", "o": ["选项"], "a": 0, "e": "解释"}]
}
```

- `a` 是正确选项的下标。
- AI 生成的课程草稿经过校验：去掉结构不合法的测验题；例题没有步骤时整体去掉。

### 8.3 考试结构

`subjects.exam_profile`：

```json
{
  "name": "编程机考",
  "duration": 150,
  "pass": 150,
  "excellent": 300,
  "sections": [
    {"name": "一星题", "count": 2, "types": ["code"], "tiers": [1, 2], "points": 100},
    {"name": "二星题", "count": 1, "types": ["code"], "tiers": [3, 4], "points": 200}
  ],
  "rules": "LeetCode 核心代码模式；每题按隐藏用例通过率给分；机考不出原题。"
}
```

| 字段 | 含义 |
| --- | --- |
| `duration` | 时长，分钟 |
| `pass` / `excellent` | 及格线 / 优秀线 |
| `sections[]` | 试卷各部分：`count` 题量，`types` 允许的题型，`tiers` 允许的层级，`points` 每题分值 |
| `rules` | 显示给考生的说明 |

- 新建学科未提供考试结构时，使用通用结构：
  - 单选 / 判断 10 题 × 4 分；
  - 多选 / 填空 5 题 × 6 分；
  - 简答 / 编程 2 题 × 15 分；
  - 60 分钟。
- 修改考试结构：`PUT /api/subjects/<id>` `{"exam_profile": {...}}`。

### 8.4 备份文件

`GET /api/export` 返回：

```json
{
  "version": "1.0.0",
  "exported_at": 0,
  "tables": {"progress": [], "attempts": [], "...": []},
  "questions": [],
  "conversations": [],
  "messages": []
}
```

- `tables` 包含：`progress` `attempts` `reviews` `goals` `skipped` `exams` `exam_skips` `study_log` `user_lessons` `resources` `proposals`。
- `questions` 只包含自己的题。
- 不包含 `model_configs`，因此不包含 API Key。
- `POST /api/import-data` 导入时，按当前用户重写 `user_id`。

## 9. 安全与隐私

| 项目 | 规定 |
| --- | --- |
| 访问范围 | 默认只监听 `127.0.0.1`。局域网访问需要用户明确开启，并在界面和文档中提示风险 |
| 鉴权 | 除静态文件、`/api/session/*`、`/api/docs` 外，全部接口要求访问码 |
| 数据隔离 | 所有个人数据按 `user_id` 过滤。用户 A 不能通过界面或接口读取用户 B 的私有题目、对话、计划、试卷、模型配置 |
| API Key | 只存在本机数据库；接口只返回 `key_hint`（末 4 位）；不写日志、不进导出、不进错误信息 |
| 代码运行 | 编程题在子进程中运行：Python 以 `-I` 隔离模式启动，有逐用例超时；Windows 下不弹出窗口。**这不是安全沙箱**：能执行任意代码，只应对可信的人开放 |
| AI 输出 | 所有写入型 AI 结果需要用户确认；结构不合法的输出被丢弃并报告，不写入 |
| 审计 | 写入 `audit` 的操作：<br>· 模型配置增删改；<br>· 用户创建与访问码重置；<br>· 题目修改、导入、分类；<br>· 课程保存；<br>· 提议执行；<br>· 成绩复核；<br>· 备份导入；<br>· 局域网开关 |
| 考试 | 进行中不下发答案，AI 接口关闭；截止时间以服务器为准 |

## 10. 开发约定

### 10.1 代码风格

**Python**
- 3.9 及以上，只依赖标准库和 `requirements.txt` 中的包。
- 模型调用一律走 `llm.chat`，不引入服务商 SDK。
- 数据库访问走 `db.q` / `db.q1` / `db.run` / `db.tx`，SQL 一律参数化。
- 修改表结构时：
  1. 在 `SCHEMA` 里加列；
  2. 在 `db.init()` 里加对应的迁移（`ALTER TABLE ... ADD COLUMN`）。

  不删除、不改名已有列。

**前端**
- 原生 JavaScript，无构建步骤。
- 每个页面在 `app.js` 中是一组：`V.<视图>`（返回 HTML）和 `V.<视图>.after`（绑定事件）。
- 插入用户内容一律经过 `esc()`；Markdown 经过 `md()`。

**样式**
- 颜色、间距使用 `style.css` 中的变量。
- 布局用 `minmax(0, 1fr)` 网格，表格外包 `.tscroll`。
- 页面在 320px 到 2560px 宽度都不能出现横向滚动。

### 10.2 界面文字

- 用用户能懂的词，例如「模块」「访问码」，不用「category」「token」。
- 按钮写动作：「保存」「交卷」「采用勾选的」。
- 错误说明发生了什么和怎么解决，例如「连不上……请确认……」。
- 规则写在用户操作之前，例如多选题计分规则写在作答区上方。

### 10.3 扩展点

| 要做什么 | 怎么做 |
| --- | --- |
| 加一个模型服务商 | 兼容 OpenAI 接口的，在 `llm.PRESETS` 加模板即可；其它协议在 `llm.py` 加一个 `_xxx_chat`，并在 `chat()` 中分派 |
| 加一个智能体 | 在 `agents.AGENTS` 加一项：名称、任务、说明、工具白名单、系统提示 |
| 加一个工具 | 在 `agents.TOOLS` 加定义和实现。只读工具直接返回数据；会修改数据的工具必须是 `propose_*`，并在 `apply_proposal` 中实现执行逻辑 |
| 加一种题型 | 依次修改：`learning.TYPE_NAMES`、`grading.grade_objective`（或单独判分）、`importer.normalize`、前端题目页的作答区和录题表单 |
| 加一个视频来源 | 在 `agents.search_links` 加搜索链接，或仿照 `youtube_search` 接入 API |
| 加一个学科（内置） | 仿照 `seed.py` 写种子数据；或在界面里建学科后导入题目 |

### 10.4 提交与分支

- `main` 分支始终可运行。每次推送到 `main`，CI 会重新打包并更新 Releases 的「最新版」。
- 较大的改动在分支上完成，测试通过后合并。
- 提交信息用中文一句话说明改了什么，例如「修复新对话第一条回复卡住」。

  - 定期测试不重复；
- 复核：
  - 必须写理由；
  - 保留原分；
  - 审计；
- 导出和接口不含 API Key。

### 11.2 CI（`.github/workflows/build.yml`）

推送到 `main` 或手动运行时触发：

| 任务 | 运行环境 | 做什么 |
| --- | --- | --- |
| 测试 | Ubuntu | 运行 `tests/test_api.py` 和 `tests/test_rules.py` |
| Windows 程序 | Windows | PyInstaller 打包 `StudyAgent.exe`，再用 `check_exe.py` 自检 |
| 安卓 App | Ubuntu + JDK 17 + Node 20 | 生成 Capacitor 安卓工程和图标，允许明文 HTTP，Gradle 打包 debug APK |
| 发布 | Ubuntu | 把 exe 和 apk 发布到 Releases 的 `latest`（每次覆盖） |

- 测试失败时不会打包。
- 安卓包是 debug 签名，适合自己安装。要上架应用商店，需要配置自己的签名密钥，打 release 包。

### 11.3 版本号

- `studyagent/api.py` 的 `VERSION` 是平台版本，会写进 `/api/system` 和备份文件。
- 改动数据格式时：
  - 提升版本号；
  - 保证新版本能导入旧版本的备份。

## 13. 已知限制

- 编程题判题不是安全沙箱，只在可信的人之间开放局域网访问。
- 自带服务器适合个人和小范围局域网。面向很多用户部署时需要：
  - 换生产级服务器（如 waitress / gunicorn）；
  - 加 HTTPS；
  - 改用正式的账号体系；
  - 加密存储 API Key。
- 手机 App 依赖电脑开着，不能离线使用。
- Java、C++ 编程题不能本机判题。
- 扫描版 PDF 需要先 OCR。
- AI 生成的题目、课程、分类、评分可能出错，平台会标明来源，并要求确认后才写入。
